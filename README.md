# mollypdf

เครื่องมือ PDF ที่ทำงานในเบราว์เซอร์ของผู้ใช้ — เนื้อหาไฟล์ไม่ถูกอัปโหลดไปที่เซิร์ฟเวอร์

## เริ่มพัฒนา

```bash
pnpm install
pnpm dev            # http://localhost:3000
```

## ตรวจสอบก่อน push

```bash
pnpm verify         # typecheck + lint + unit tests + build
pnpm test:browser   # end-to-end บน Chromium จริง (ต้อง build ก่อน)
```

## โครงสร้าง

| ที่อยู่ | หน้าที่ |
| --- | --- |
| `app/` | หน้าเว็บและ API route |
| `components/` | UI ที่ใช้ซ้ำ — dialog, ตัวเลือกเครื่องมือ, แผงลายเซ็น, แผงอ่านออกเสียง |
| `lib/pdf/` | ตรรกะการจัดการ PDF ทั้งหมด แยกออกจาก UI เพื่อให้เทสต์ได้ |
| `lib/tools/` | registry ของเครื่องมือ และ dispatcher ที่รันงานแต่ละอย่าง |
| `db/` | ตัวนับการใช้งาน (ไม่บังคับ — เว็บทำงานได้โดยไม่มีฐานข้อมูล) |
| `tests/` | unit tests + ชุด end-to-end บนเบราว์เซอร์จริง |

## หลักการที่ยึดในโค้ดนี้

1. **ห้ามล้มเหลวเงียบ** ถ้าเครื่องมือทำงานไม่สำเร็จ ต้องไม่สร้างไฟล์ให้
   และต้องบอกสาเหตุที่ผู้ใช้แก้ได้ กรณีที่ชัดที่สุดคือ `ปิดข้อมูลสำคัญ` —
   ถ้าหาคำที่ระบุไม่พบ จะไม่มีไฟล์ออกมา
2. **คำโฆษณาต้องตรงกับโค้ด** ถ้าการ์ดบอกว่าทำอะไรได้ ต้องทำได้จริง
   ทุกคำกล่าวอ้างเรื่องความเป็นส่วนตัวตรวจสอบได้จากแท็บ Network
3. **หน่วยความจำต้องคงที่** งานที่ต้องเรนเดอร์หน้าเอกสารจะทำทีละหน้าเสมอ
   ไม่เก็บ canvas ของทั้งเล่มไว้ในหน่วยความจำ
4. **ภาษาไทยเป็นพลเมืองชั้นหนึ่ง** การตัดคำ การนับคำ การตัดบรรทัด
   และการฝังฟอนต์ ถูกออกแบบสำหรับภาษาไทยก่อน ไม่ใช่ปรับจากภาษาอังกฤษทีหลัง
